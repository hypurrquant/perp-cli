# Changelog

All notable changes to `perp-cli`. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning follows [SemVer](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- **Ondo `market kline`:** candles opened at the request minute (`:01`, `:06`) instead of the interval boundary, and the last row was a zero-volume candle opening after the requested end. `GET /v1/perps/candles` buckets minute-based resolutions from the requested `from`; the adapter now floors `from` to the interval boundary (day / week / month are already venue-aligned) and drops candles opening after `--end`. The endpoint stays the authenticated `/v1/perps/candles` (string decimals); without a registered Ondo key `market kline` refuses with `NO_SIGNER_AVAILABLE`.
- **Lighter / Lighter RH `market funding`:** returned one row stamped "now" (the current `/funding-rates` value, a fraction per 8 h) whatever `-l` was. It now reads the settled history, `GET /api/v1/fundings` (apidocs.lighter.xyz/reference/fundings): the last `-l` hourly settlements (1..750), converted from the venue's unsigned percent-per-hour + `direction` to a signed fraction per 1 h (`intervalHours: 1`, `rateKind: "lastSettled"`). Funding bots (`scoreFunding`) normalize each history row by its own `intervalHours`.
- **`market funding` rows** on hyperliquid (incl. HIP-3), pacifica, lighter, lighter-rh, aster, ondo, arcus, qfex and risex now carry `intervalHours` and `rateKind: "lastSettled"`, like grvt / extended (Aster: the market's interval from `/fapi/v3/fundingInfo`, null when the venue lists none). Hyperliquid's window was fixed at 24 h, so `-l` above 24 returned 24 rows; it now spans `-l` hours.
- **`market info|list|prices` `fundingHours`** is set where the venue definition fixes it: hyperliquid 1, pacifica 1, lighter 8, lighter-rh 8 (was null).
- **Pacifica `market prices`** printed the raw `/info/prices` rows (`funding`, `mark`, `mid`, `oracle`, `next_funding`, …). It now prints the same normalized market rows as every other venue (`symbol`, `markPrice`, `indexPrice`, `fundingRate`, `volume24h`, `openInterest`, …, from `getMarkets`); the human table uses the common Mark / Index / Funding columns.
- **`market list|prices` without `-e`** fanned out to the 9 account-role venues only, leaving out the market-data-only venues (TxFlow, Variational, GRVT, Extended) although each has a public adapter. Every venue with the `marketData` role is now included (13 on mainnet); the human output footnotes unofficial-API venues (TxFlow). Wall time is unchanged in practice (venues are read in parallel: 6.0 s → 6.3 s on 2026-10-19 with a warm GRVT margin-rules cache; a cold GRVT cache adds its ~7 s margin_rules fan-out).
- **RISEx `market kline`: unsupported intervals returned 1m bars.** `/v1/markets/id/<id>/trading-view-data` answers an interval it does not serve (3m, 30m, 2h, 8h, 12h, 3d — verified live 2026-10-19) with 1m candles and no error, and the adapter listed `30m` and never checked the rows. The interval table is now the live-verified set `1m 5m 15m 1h 4h 1d 1w` (`30m` dropped, `1w` added); anything else is `INVALID_PARAMS` listing them, and a row whose `interval` differs from the request is `EXCHANGE_ERROR` — never returned. The same row-interval guard now applies to the other venues whose candle rows state their interval: Hyperliquid (incl. HIP-3), TxFlow and Pacifica (`i`). Aster, Lighter (`i` there is a trade id), Ondo, Arcus, QFEX, GRVT and Extended rows carry no interval field.
- **TxFlow `market kline`:** `candleSnapshot` answers `200 []` for a window above ~3000 bars (measured 2026-10-19: 3000 bars → rows, 3050 → `[]`, at 1m / 5m / 1h / 1d), so a 200-day 1h range came back empty. Ranges are now read in windows of ≤ 2900 bars (max 50 requests, else `INVALID_PARAMS`), merged, deduped and sorted. `3d` / `1w` / `1M` were offered but return `[]` for every window; they are now `INVALID_PARAMS` (supported: 1m 3m 5m 15m 30m 1h 2h 4h 8h 12h 1d).
- **TxFlow `market list|prices|info` `volume24h`** was always null; it is now `dayNtlVlm` (24 h USD notional) from `POST /info {type:"allMarketTickers"}`, joined by `instrumentId` = perpMeta `index` (spot rows ≥ 10000 ignored; `""` → null). Still labelled unofficial. Funding keeps the WS `allAssetCtxs` snapshot (it carries `prevFundingTime`, which proves the one-hour interval; `allMarketTickers` does not).
- **Extended `market kline` / `market funding` silently capped.** The server answers at most **2800** candles and **1000** funding prints per request (measured 2026-10-19; the documented `limit` max is 10,000; no pagination field, no error), so a 3-day 1m range returned only the newest 2800 bars and `-l 1500` returned 1000 rows. Both now page backwards (`endTime` = just before the oldest row returned) until the range / limit is covered; a page equal to the cap always triggers another page (max 50 pages, else `INVALID_PARAMS` up front for klines). `1M` is added (`P30D`, calendar-month candles). Mixed-case symbols (`kNOT`) resolve by their own wire casing first, and `KNOT` also tries the venue's `k` (×1000) prefix, before the ~1 MB full listing.
- **GRVT `market kline` dropped older bars.** The `next` cursor runs dry after ~1000 bars (live: page 2 = 2 rows, `next` ""), so a 2-day 1m range returned 1002 of 2878 bars. Pages now walk `end_time` back to just before the oldest bar returned until `start` is covered (the cursor is not used); verified live: 40 days of BTC 1m = 57,583 bars in 58 pages back to the start (17 one-minute gaps — minutes GRVT publishes no bar for). Max 50 pages, refused up front with `INVALID_PARAMS`. An off-grid `--start` is floored to the interval (GRVT answered a truncated, off-grid first bar: 4h from 05:07 → a 06:00–08:00 bar); for calendar intervals (3d … 4w) a truncated leading bar is dropped.
- **GRVT trades / funding limits:** trades are newest first like every other venue (the venue answers oldest first); `--limit` outside 1..1000 (the measured server cap, no cursor) is `INVALID_PARAMS` instead of being clamped (0 / -5 became 1). Funding history sends the requested limit (it was clamped to 1000; the venue serves up to 10,000 in one answer).
- **RISEx `market funding` capped at 168 rows:** the API defaults `start_time` to now − 7 d, so any `-l` ≥ 169 returned 168 rows. The window (`limit` hours back) is now sent explicitly and pages are followed with `page` / `has_next_page` (1000 rows per page).

### JSON contract changes

- `market funding` (all venues with a history): rows gain `intervalHours` (number | null) and `rateKind` (`"lastSettled"` | null) — additive.
- `market funding -e lighter|lighter-rh`: `rate` is now a settled fraction **per 1 h** (`intervalHours: 1`) and `time` is the settlement time; it was a single current rate per 8 h at the request time. `price` is null (the endpoint carries no mark/oracle price; it was the mark price before). Plainly wrong before, so changed.
- `market prices -e pacifica`: rows are the normalized market shape (`markPrice`, `indexPrice` = oracle, `fundingRate`, `volume24h`, `openInterest`, `maxLeverage`, `sizeDecimals`, `stepSize`, `fundingHours`, `marginTiers`) instead of the raw venue fields `funding` / `mark` / `mid` / `oracle` / `next_funding` / `open_interest` / `volume_24h` / `yesterday_price` / `timestamp`. Plainly wrong before (one venue with a different shape); `mid` is no longer emitted here (`perp -e pacifica market mid <sym>` gives it).
- `market list|prices` (no `-e`): `data.exchanges` gains the keys `txflow`, `variational`, `grvt`, `extended` — additive.
- TxFlow market rows: `volume24h` null → the venue's 24 h notional (string) where it trades.
- GRVT `market trades`: row order newest first (was oldest first).
- `fundingHours` on hyperliquid / pacifica / lighter / lighter-rh market rows: null → 1 / 1 / 8 / 8.

## [0.15.0] — 2026-10-19

### NEW: Extended (formerly X10, Starknet) — read-only market data (`perp -e extended`, aliases `ext` / `x10`)

- **Phase 1, market data only**, through Extended's **official** public REST API (api.docs.extended.exchange; mainnet `api.starknet.extended.exchange/api/v1`, testnet Sepolia `api.starknet.sepolia.extended.exchange/api/v1` via `-n testnet`). Keyless; no signing. Every write / account / funds / agent / builder / bot path refuses with `CAPABILITY_UNSUPPORTED` before any request, also under `--dry-run` — remediation "Extended is read-only (market data) in this version; trading is planned for a later release". New refusing subcommands `funds deposit|withdraw extended`.
- **Works:** `market list|prices|info|book|trades|funding|kline -e extended` and `perp health` (an **official** venue: counted in `healthy`). Funding is **unverified** (below): Extended rows appear in `arb scan --rates` / `--compare` / MCP `get_funding_rates` only with `--include-unverified` / `includeUnverified` (display only, never ranked for trading, not saved to funding history). `arb scan --basis` and arb execution stay trading-venue only.
- **Markets:** `type: "PERPETUAL"` with `status` ACTIVE or REDUCE_ONLY (the `active` flag is not a listing state: DELISTED / PRELISTED rows carry `active: true`); SPOT rows excluded. A malformed row is skipped with a warning (`EXCHANGE_ERROR` only for envelope drift or when no row parses). Rows add `assetClass` (crypto / equity / etf / index / commodity / fx / preIpo from `category` / `subCategory`; unknown → skipped with a warning; human `market list` shows a "Class" column), `venueSymbol` (wire name), `canonical`, `tickSize` (`minPriceChange`), `minSize` (`minOrderSize`), `stepSize` (`minOrderSizeChange`), `maxLeverage`, `marginTiers` (from `riskFactorConfig`, 1 / riskFactor, tiers available to users), `tradable` (false while `REDUCE_ONLY` or `isOffHours`), `status`, `isRfq`, `tradingHours`, `isOffHours`, `fundingRateKind`, `nextFundingTime`. OI = `openInterestBase` (base units); unknown values are `null`. Per-market reads (`book`, `trades`, `funding`, `kline`) resolve the symbol with `GET /info/markets?market=<name>` (~2 KB) instead of the ~1 MB listing.
- **Symbols:** `assetName` without the `_24_5` suffix (`TSLA_24_5-USD` → `TSLA`, `SPX500m-USD` → `SPX500M`). Two listed markets with one symbol (a ticker migration such as `NOW_24_5-USD` → `NOW-USD`): the single ACTIVE row is kept, else both are skipped — warned either way. Canonicals: crypto / equity / ETF by ticker; index / commodity / fx via `EXPLICIT_CANONICAL` (`XAU` GOLD, `XAG` SILVER, `WTI` CRUDE_OIL_WTI, `XBR` CRUDE_OIL_BRENT, `SPX500M` SPX, `TECH100M` NDX, `USDJPY`). Never matched: RWA tickers that are crypto tickers elsewhere (PURR = Hyperliquid Strategies Inc., QNT = Quantinuum, BB = BlackBerry, ON = ON Semiconductor, ADI = Analog Devices, BOT = RoboStrategy), XIAOMI (~7.8× the Lighter / Aster price — a different unit) and the crypto `SPX` (SPX6900).
- **Funding:** applied once per hour; `marketStats.fundingRate` is a **fraction per hour** (crypto interest component 0.01 % / 8 h → `0.000013`), published **rounded to 6 decimals** (0.000001 / h ≈ 0.876 % APR resolution), and is the current hour's **accruing** rate (recomputed every minute); `nextFundingRate` is the next application timestamp. `market funding` reads `/info/<market>/funding` — the applied hourly prints (`rateKind: "lastSettled"`, `intervalHours: 1`, `annualizedPct`). **`fundingVerified: false`**: not checked against an account funding payment, and `_24_5` equities print 0 while their underlying is closed (TSLA_24_5: 34 of 43 weekend prints), so × 8760 overstates them. Partial evidence kept: `src/__tests__/fixtures/extended/funding-settlement-evidence.json` (one recorded settlement: the last accruing value equals the applied print on 8 markets).
- **Rate limit:** docs default tier 1,000 requests / minute per IP → limiter 15 / s sustained, burst 50. A `User-Agent` header is sent (mandatory; none → HTTP 403).
- **WS:** no `perp-cli/ws` codec — Extended streams are one socket per stream URL with no subscribe frame, which the codec model (one URL + subscribe frames) does not fit without a transport change (see the ws library reference).

### NEW: GRVT — read-only venue (`-e grvt`, alias `grv`; market data only in this version)

- **Official Market Data REST API** (api-docs.grvt.io/market_data_api/, `POST https://market-data.grvt.io/full/v1/…`, keyless; testnet `market-data.testnet.grvt.io`): `instruments` (perpetuals only), `ticker` (one per market — GRVT has no bulk ticker), `margin_rules` (max leverage + notional tiers), `book`, `trade`, `funding`, `kline`. Counted among the official venues in `perp health` (one `instrument` read as the probe).
- **`market list|prices|info`:** mark / index / last / best bid / best ask / open interest (base) / 24 h volume (buy + sell quote volume, USDT), tick, minimum size and notional, max leverage and margin tiers. `stepSize` is null: GRVT publishes no lot step (`base_decimals` is the signing multiplier). Symbols are the base ticker (`BTC`, `KPEPE`, `XAU`); `BTC_USDT_Perp` is accepted; unknown symbols → `SYMBOL_NOT_FOUND`.
- **Funding:** the interval is per market (`funding_interval_hours`: 124 markets 8 h, 60 markets 4 h on 2026-10-19). GRVT quotes percent per interval (settled history "percentage points"; the ticker prints the same magnitude although its schema says "centibeeps"), converted exactly to a fraction per interval with basis `perHours: <interval>`. Market rows carry the INDICATIVE rate of the running interval (`fundingRateKind: "predicted"`, `nextFundingTime`); `market funding` is the settled history (`rateKind: "lastSettled"`, `intervalHours` per row). Unverified (`fundingVerified: false`, not checked against settled payments yet): GRVT joins `arb scan --rates` / `--compare` only with `--include-unverified`, display only.
- **Symbol mapping:** crypto by ticker (+ `KPEPE`/`KSHIB`/`KBONK` → `1000…`), commodities explicit (`XAU` GOLD, `XAG` SILVER, `CL` WTI, `BZ` Brent; NATGAS / COPPER / XPT / XPD unmatched). Equities / ETFs match by ticker only from a reviewed whitelist (85 of the 98 live EQUITY markets); pre-IPO (OPENAI, ANTHROPIC, SPACEX) and ambiguous tickers (BRKB, SKHY, SAMSUNGEM, DRAM, …) are never matched, and an unreviewed new EQUITY ticker is explicit-only (canonical null) with a one-time warning.
- **MCP:** `get_markets` / market-data meta now label every venue whose funding is unverified — rows `fundingVerified: false`, meta `fundingVerified: false` + `fundingNote` — for official venues too (GRVT, QFEX gain the label; TxFlow output unchanged), on the public path and on the credentialed adapter path alike (one shared row label).
- **Rate limits** (help.grvt.io, every tier): Ticker / MiniTicker / GetInstrument 1500 per minute, all other market-data reads 500 per minute — two token buckets per network sized so no 60 s window exceeds them; the per-market fan-out keeps 8 requests in flight.
- **Request budget:** the registry path (MCP `get_prices` / `get_markets`, `market://prices`, `arb scan`, dashboards) is price-only — instruments + one ticker per market (185 requests), both reused in-process for 15 s, so repeated MCP calls cost nothing; `maxLeverage` / `marginTiers` are null there. `margin_rules` is read only by `market list|prices` (all markets) and `market info` (one market: directory + 1 ticker + 1 margin_rules), and file-cached per network with a 6 h TTL PER INSTRUMENT (each entry keeps its own `fetchedAt`; a later read never extends an older entry). Those rows carry `leverageAsOf` (ISO time of the margin-rules read; null when not read).
- **Per-market isolation:** a market whose ticker read fails is dropped with a warning naming it (like a market without a mark price); a failed margin_rules read leaves that market's leverage null (warned, not cached). The venue fails only when every ticker fails, or on `RATE_LIMITED`, which also stops the remaining requests.
- **Order book** is sliced to the requested depth; **klines** follow GRVT's `next` cursor (1000 bars per page, up to 10 pages, then a warning). The ticker's undocumented `session` field is not mapped (`session: null`).
- **Refused before any request** (`CAPABILITY_UNSUPPORTED`, remediation "GRVT is read-only (market data) in this version; trading is planned for a later release"): every trade / account / portfolio / funds (incl. `funds deposit|withdraw grvt`, also under `--dry-run`) / agent / builder / strategy / background-job / arb-exec path, and `setup --venues` / `--default-venue` selection (now `CAPABILITY_UNSUPPORTED` for any registered market-data-only venue instead of "unknown trading venue"). No keys, no signing, no account code.
- **No perp-cli/ws codec:** GRVT's public WS (`wss://market-data.grvt.io/ws/full`, JSON-RPC `subscribe`) has per-instrument selectors only (no all-markets stream) and allows 150 concurrent streams / 300 subscriptions per minute — fewer than its 184 perpetuals, so `allMarkets` cannot be served. `perp-cli/ws` and `@hypurrquant/perp-ws` are unchanged.

### NEW: Variational (Omni) — read-only venue (market data)

- **`-e variational`** (aliases `var`, `omni`): Variational Omni through its OFFICIAL read-only API, `GET https://omni-client-api.prod.ap-northeast-1.variational.io/metadata/v2/stats` (docs.variational.io/technical-documentation/api) — one keyless call for every market (575 on 2026-10-19: 557 perpetuals, 18 swaps). Variational has no public trading API yet, so the venue is market data only: every trade / account / portfolio / funds / agent / builder / bot path refuses with `CAPABILITY_UNSUPPORTED` before any request, also with `--dry-run` ("Variational is read-only (market data) in perp-cli; Variational has no public trading API yet"). No testnet; no WebSocket is documented (no ws codec).
- **Commands:** `market list | prices | info | funding | book` (the funding cell carries its interval, e.g. `+0.0079%/8h`), `perp health` (counted as an official venue), Variational prices in the MCP price tools, and Variational funding rows only on request: `perp arb scan --rates --include-unverified` / `--compare <sym> --include-unverified`, MCP `get_funding_rates` `includeUnverified` — display only, never ranked, never saved to the funding history. `arb scan --compare US500` points to `SPY`.
- **Funding is UNVERIFIED** (`fundingVerified: false`): the rate is a moving prediction, there is no public account API to check it against settled payments, and the accrual hours of equity / ETF perps are not documented.
- **Funding units:** per-market interval (`funding.interval_seconds`: 1h / 4h / 8h perps), positive = longs pay. `fundingRate` is the documented `funding.last.interval_rate` for one interval (basis `perHours(interval / 3600)`); the comparison normalizes it to hourly / APR like every other venue. It is a `predicted` rate — recomputed during the window for the payment at `next_timestamp` (`next` equals it). Each row is checked against the venue's own `annualized_rate` (× interval / 365 d); a row that disagrees gets no rate (warned). `market funding <sym>` shows the current terms (per interval, hourly, APR %, next time) — the API publishes no funding history.
- **RFQ, not an order book:** Variational's single market maker (OLP) quotes every trade. `market book` shows its INDICATIVE quotes at fixed notionals (min order, $1k, $100k, $1M where published; `kind: "rfqQuotes"`, with `updatedAt` — may be up to 600 s old), labelled as RFQ quotes; `getOrderbook` / trades / candles are `CAPABILITY_UNSUPPORTED`.
- **Swaps** (`XAU-SWAP`, `US500-SWAP` …): daily-funded TradFi swaps with separate long / short rates — shown on Variational rows (`swapFunding`), `fundingRate` null, never matched across venues.
- **Symbols:** perps by base (`BTC`), swaps keep the suffix. Crypto by ticker identity; TradFi perps classified explicitly (equity / ETF by ticker; XAU / XAG / CL / BZ → GOLD / SILVER / CRUDE_OIL_WTI / CRUDE_OIL_BRENT; pre-IPO and other commodities unmatched); `US500-PERP` is the SPDR S&P 500 ETF → `SPY`, not the index. `SPX` (SPX6900) and `QNT` (Quant) are never matched — the exclusions Hyperliquid / Aster / Lighter already apply. An unclassified perp whose name reads like a company / fund is never matched. Other same-ticker different assets (ZETA, DIA, BEAM vs an equity / ETF elsewhere) are excluded by the cross-venue price guard.
- **Null handling:** no index price, tick, lot, leverage or base-unit open interest is published → null; open interest is reported in USD, single-sided (`openInterestUsd`). A malformed listing is dropped with a warning naming it; payload drift is `EXCHANGE_ERROR`.
- **Rate limit:** documented 10 requests / 10 s per IP — enforced by the venue limiter; one stats body (only of the documented shape) serves every reader for 5 s (file cache, raw JSON) plus one in-flight request per process, so `market list` + `info` + `book` + `funding` + `prices` in the window cost one request. HTTP 429 → `RATE_LIMITED` with `retry_after_seconds`.
- **Shared cache:** `cache.ts` writes each entry through a tmp file unique per writer (`<key>.json.<pid>.<random>.tmp`), so concurrent processes never rename each other's half-written file.
- **Adapters:** `ExchangeAdapter` gains the optional capabilities `getRfqQuotes` (RFQ venues: `market book`) and `getFundingTerms` (no funding-history API: `market funding`).
- **Regions:** Variational's Restricted Persons list (US, Canada, sanctioned regions, Taiwan …) is shown as a warning (never enforced).

### RISEx: read-only in 0.15.0 (trading in a later release)

- **Owner decision 2026-10-19 — new venues ship in phases:** phase 1 (this release) is read-only data for **RISEx** and **Derive** (options, see below); trading follows in a later release. RISEx is an official API (`apiStatus: "official"`) and counts as an official venue in `perp health`.
- **Works:** RISEx market data (`perp -e risex market list|prices|info|book|trades|kline|funding`), hourly verified funding in `arb scan` / `arb scan --rates` / funding comparisons, `perp health`, MCP market-data tools, and account reads that need only the master address (`portfolio`, `account positions|orders|history|trades|funding-history` — public by address, nothing is signed, no signer needed). `wallet agent verify risex` (an on-chain read) keeps working for signers registered by an earlier build.
- **Shipped but disabled:** the RISEx trading path (EIP-712 session-signer permits, trading-only on-chain signer restriction, market / limit GTC·IOC·FOK·ALO, cancel, cancel-all, leverage, margin mode, `wallet agent approve|revoke risex`) is in the package with its tests, but switched off by one flag (`src/exchanges/venues/risex-release.ts` `RISEX_TRADING_ENABLED = false`, which removes RISEx's `trading` role). Every gated entry point refuses with `CAPABILITY_UNSUPPORTED` ("RISEx trading is planned for a later perp-cli release; in this version RISEx is read-only", remediation app.rise.trade) before any key is read or request is sent — **also under `--dry-run`**: `perp trade …` writes with `-e risex`, `trade multi` legs, `arb exec|auto` legs, every `strategy …` command (bots, `strategy run`, `strategy start <config>`, `strategy plan execute`, TWAP / grid / DCA, `--exchanges` legs — refused before any adapter or key, also with `--dry-run`), `wallet agent approve|import|revoke|rotate risex` (`revoke --force` / `--local-only` still clears the local record — nothing is signed), `perp setup --venues risex` / `--default-venue risex` (RISEx is no longer offered by setup), `funds faucet risex`, and the MCP `trade_preview` / `trade_execute` / `trade_close` tools (refused before any credential lookup). `arb scan --basis` lists trading venues only, so RISEx is not in it. Funding opportunities (`arb scan`, MCP `arb_scan`) keep RISEx rows and carry new `executable` / `readOnlyLegs` fields: a pair with a RISEx leg is `executable: false` (human output: "(read-only)"). While gated, a RISEx read never opens a stored signer key.
- **Funds:** unchanged — deposits / withdrawals are done in the RISEx app (`funds deposit|withdraw risex` → `CAPABILITY_UNSUPPORTED`).
- **Venue definitions:** new required field `VenueDefinition.gatedRoles` (roles implemented but switched off in this release, with the refusal reason / remediation; `null` on every other venue). `roleUnsupported()` uses it, so the phase refusal is uniform everywhere.
- No WebSocket codec for RISEx: `perp-cli/ws` is unchanged (RISEx is not a WS venue).

### NEW: Pacifica Print (`perp print`) and vaults (`perp vault`)

- **Print** (docs.pacifica.fi/print): strike orders that earn a premium every cycle and fill only at a cycle checkpoint, at the target. Reads (unauthenticated GET, never signed): `print games` (`/game/config`: cycle, max leverage, product / pool deposit caps, allowed target range), `print quote` (local validation + preview: notional, size on fill, `docsLiquidationPrice`, `maxLoss`, lock period; `estimatedPremium: null` — the venue's premium preview `preview_game_account` is a signed request and is never called on a read path), `print positions` (`/game/accounts`), `print history` (`/game/history_summary`, `--limit` / `--cursor`), `print events <printAddress>` (`/game/history`). Writes: `print deposit` (POST `/game/deposit`, `deposit_to_game`, fresh `idempotency_key`, `--cycles` → `total_segments`) and `print cancel` (POST `/game/end`, `end_game` — not in the API docs; the payload `{game_account}` is the one app.pacifica.fi sends; only a `printing` order).
- **Validation (docs):** deposit ≥ 10 USDC, ≤ 6 decimals, ≤ the product cap, ≤ `available_to_withdraw`; whole-number leverage 1 … product max; target on the correct side of the mark, 0.5% … 10% / 20% / 40% for 1 / 7 / 30-day cycles, on the market tick; cycles 1 … 1000. A product with an undocumented cycle kind is refused (`CAPABILITY_UNSUPPORTED`), never given a guessed range.

### NEW: Pacifica Atomic basket — `perp -e pacifica trade atomic`

- **`trade atomic --long SYM[:W]... --short SYM[:W]... --usd <total>`** (Pacifica only; other venues → `CAPABILITY_UNSUPPORTED`): the docs' Atomic order (trading-on-pacifica/order-types/strategies/atomic) — up to 5 legs per side, each market once, weights relative, `--usd` split by weight and converted at each leg's mark price. Every leg is a `create_market_order`-signed `CreateMarket` action, all sent in ONE `POST /api/v1/orders/batch` (docs batch-order). Not all-or-nothing: the result is per leg (filled / partly filled / not filled / refused / unknown), each fill read back from `history_by_id`. Options: `--reduce-only` (every leg; `--long` legs must close shorts and `--short` legs longs, checked against the positions before sending), `--slippage-bps` (per leg, same 1..5000 bound as `trade market`), `--force` (risk limits only). Each leg's `client_order_id` is a generated UUID, reported.
- **Validation before signing:** lot flooring, the market's `min_order_size` (USD) × (1 + slippage bound) per leg (so a leg stays above the minimum at its worst allowed fill), a positive mark (`PRICE_STALE`), perp markets only, missing `/info` fields → `EXCHANGE_ERROR` (no defaults); opening legs go through quarantine + local risk limits like `trade market`.
- **Leg tracing:** the batch docs' `CreateMarket` result carries `order_id: null`, so an accepted leg is traced by its own `client_order_id` (open orders / order history, up to 6 reads 500 ms apart), then its fill is confirmed from `history_by_id` (`terminalOnly`); legs are confirmed in parallel. All legs are signed with ONE timestamp; if signing leaves under 1.5 s of the 5 s signature window (slow signer), nothing is sent (`ORDER_REJECTED`, `sent: false`).
- **Rate limit (with the Pacifica credit limiter):** a batch is reserved per action (docs rate-limits: "Standard request/action" 1 credit, cancellation 0.5; no batch-specific cost is documented, so the conservative per-action reading) — `PacificaClient.batchOrders` / `awaitBatchCapacity`, `pacificaBatchCost`. Atomic waits for the whole batch's capacity BEFORE signing (up to 15 s, else `RATE_LIMITED`, nothing signed); after signing, the throttle may wait only for what is left of the 1.5 s expiry guard (≤ 2 s) — a longer wait fails fast with `RATE_LIMITED` (`sent: false`) instead of sending an expired batch.
- **Risk:** opening legs go through quarantine and the per-leg limit; the basket as a whole is also checked — total notional against the total-exposure limit, and open positions + legs on new markets against max positions (`--force` skips both).
- **Outcomes:** every leg filled → `ok`; any leg not confirmed (a client order id that never resolves, no settled `history_by_id` row, an unreadable / mismatched batch response, a timeout / 5xx / undocumented 4xx after sending) → `ORDER_PENDING`, never resubmitted, and the leg's symbol is quarantined (a batch failure other than 400 / 429 quarantines every leg); nothing filled → `ORDER_REJECTED`; otherwise `ORDER_PARTIAL` (details list every leg). HTTP 400 on the batch = the documented whole-request refusal (`ORDER_REJECTED`); 429 → `RATE_LIMITED`.
- **`--dry-run`** prints the exact batch body (signature replaced by a placeholder) and each leg's canonical signed message; nothing is signed or sent. A configured, approved builder code rides on every leg (`builder_code`, as on `trade market`).
- **Not available:** Pacifica's Chase, OCO, Trailing Stop, Swarm, Trigger Swarm and Conditional Market / Limit have no documented API / SDK path as of 2026-10-19 — no REST endpoint, signing operation type or order type code (api/signing/operation-types, batch-order action types, the `order_type` / `ot` lists; none in the python-sdk or Pacifica MCP server). Nearest equivalents: `trade twap` (≈ Swarm) and `trade tpsl` (≈ OCO bracket exit).
- **Result shape:** per-leg `outcomes[]` instead of one `OrderResult` — an intentional exception like `trade multi` (design §13.7).
- **WS:** no new `account_order_updates` `ot` codes are documented; Atomic legs are `market`. Covered by tests: unknown `ot` values pass through verbatim, a missing one is `null`.
- **Library:** `PacificaClient.signBatchAction(type, payload, account, sign, { timestamp, expiry_window })` (signs one batch action with a fixed header, sends nothing); `BatchActionType` gains the documented `CreateMarket`, `Edit`, `SetPositionTpsl`, `CancelStopOrder`.

### NEW: Pacifica REST reads its rate-limit headers and slows down before HTTP 429

- **Headers (docs: rate-limits; live mainnet 2026-10-19):** `ratelimit: "credits";r=980;t=22` (remaining, seconds until refresh) and `ratelimit-policy: "credits";q=1000;w=60` (quota, window) — credits ×10 (`q=1000` = the documented 100 credits / 60 s per IP). Parsed strictly (`src/pacifica/rate-limit.ts`): absent / malformed → no info, never a guess. CloudFront cache hits (`x-cache: Hit…`, `age`) replay another caller's headers and are ignored.
- **Pre-send throttle (cost-aware):** every Pacifica REST request (adapter GET / signed POST, spot, and the public `/info` + `/info/prices` fetchers) checks the last observed quota minus the credits still in flight. A read must leave a 12-credit reserve (largest documented heavy GET); a write needs only its own cost (1 credit, cancels 0.5), so an amend's replacement leg is never blocked by the read reserve. Otherwise the request waits for the window to refresh — at most 15 s (signed actions wait before signing; after signing at most 2 s, inside the 5 s `expiry_window`). Longer → fails fast with `RATE_LIMITED` (`details.sent: false`, `retryAfterMs`, remediation): nothing was sent. The public fetchers used by `arb` / dashboards never wait (fail fast, the venue is skipped). The cost is reserved synchronously before any await (concurrent `Promise.all` requests cannot overshoot); a late response with a higher `r`, or one with a different `q`, is ignored within the window; `t` / `Retry-After` are clamped to the window + 1 s; elapsed time uses a monotonic clock. The venue-health ping (`pingPacifica`) records headers but is never throttled.
- **HTTP 429 is structural:** `RATE_LIMITED` by status code (no longer by matching "429" in the message), with `httpStatus: 429`, `sent: false` and `retryAfterMs` from `Retry-After` or the `ratelimit` reset. Nothing is retried; a write is never resubmitted. A 429 (or local refusal) on an order / cancel is reported as definitely not executed: cancel / cancel-all / amend report it as refused (failed), not `ORDER_PENDING`. "429 = not executed" is our reading of the docs ("When credits are exhausted, requests return HTTP 429"); Pacifica does not state it explicitly.
- **Scope:** state per network (REST base URL), credential tier (no key = IP quota; an API Config Key has its own) and request kind — signed POSTs apart from keyless GETs, since credits are shared per main account and scale with its fee tier (a signed response can report an account quota while keyless GETs report the IP quota). Process-local: several perp-cli processes on one IP share the venue quota unseen.

Cancel outcome unknown → `ORDER_PENDING`; cancelled but fill unreadable or replacement refused → `ORDER_PARTIAL { cancelled, placed: null }`. Unknown TIF (order not placed by perp-cli) → `CAPABILITY_UNSUPPORTED` "original order attributes unknown" — pass `--tif`.

- **Ondo amend** records the TIF source and `filledBeforeCancel` / `replacedSize` in `execution.notes`.
- **Pacifica `iocOutcomeOf`** parses the market order's terminal `history_by_id` row carried in the raw result (`fillReport`), so copies of the result work; `null` when not proven.
- **`trade cancel-stop`** works on Pacifica (it targeted an adapter property that did not exist); other venues → `CAPABILITY_UNSUPPORTED` pointing at `trade cancel`.

### Uniform trade surface (design `docs/DESIGN-venue-abstraction.md` §13.3, §13.6, §13.7, §13.10 #8/#13/#14)

#### BEHAVIOR CHANGES
- **Every venue's `trade market/buy/sell/limit/stop/edit/cancel` goes through `TradingV2`** — native on Ondo / Arcus, a composition wrapper (`src/exchanges/legacy-trading-v2.ts`, `tradingV2Of()`) on Pacifica / Hyperliquid / Lighter / Lighter RH / Aster that calls the same legacy adapter send methods (in-process `ExchangeAdapter` methods still return raw venue responses). Capability pre-validation (`validateOrderRequest`), dry-run, client-id tracking and risk checks are unchanged.

### Uniform slippage (design `docs/DESIGN-venue-abstraction.md` §13.2, §13.10 #1–#2)

#### BEHAVIOR CHANGES
- **Every market-type order is slippage-bounded by one resolved value** — precedence `--slippage-bps` → `settings.slippageBps.<venue>` → **`settings.defaultSlippageBps` (new, shipped default 50 bps)**, resolved in one place (`resolveSlippage()`, `src/exchanges/slippage.ts`). Applies to entries, closes (`close` / `close-all` / `flatten` / `reduce`), bots/arb (no flag → venue/default), MCP `trade_execute` (new optional `slippageBps`) and spot `spot-buy/spot-sell`. Out-of-range bounds (`< 1` or above the venue maximum, e.g. Arcus 1000) fail with `INVALID_PARAMS` before sending — never clamped. Thin books may now partially fill / not fill where the old wide bounds swept.
  - Pacifica perps: `slippage_percent` = bps/100 (was hard-coded `"1"` = 1%). Hyperliquid spot / Lighter spot: protection = reference ± bps (was 5%). Ondo perp market orders are always IOC LIMIT at the protection price (previously native market unless a bound was configured). Ondo / Arcus / Pacifica spot no longer fail with `SLIPPAGE_REQUIRED`.
  - Hyperliquid perps, Lighter perps and Aster (perp + spot) still use their pre-existing internal protection until their adapter lanes land (§13.10 #15 step 2).
- **`--slippage-bps` is accepted on every venue** (`trade market/buy/sell`, `close`, `close-all`, `flatten`, `reduce`, `spot-buy/spot-sell`); the legacy-venue `CAPABILITY_UNSUPPORTED` rejection is gone.
- **`-s / --slippage <pct>` removed** from `trade market/buy/sell` (it was never applied). `--split`'s `--max-slippage <pct>` is a split-only per-slice price-impact cap, unrelated to the market-order bound.
- **`SLIPPAGE_REQUIRED` error code removed.**
- **Strict settings parsing** — a malformed `~/.perp/settings.json` (invalid JSON, non-object, invalid `slippageBps` / `defaultSlippageBps`) now throws `INVALID_PARAMS` with the file path and how to fix it, instead of silently loading all defaults (which could also overwrite stored agents on the next save). A missing file still means defaults.
- **`perp settings show`** lists `default <bps> (shipped default)`; `--json` adds `defaultSlippageBpsSource`. `perp settings set defaultSlippageBps <n>` (validated against the tightest venue maximum) and `perp settings unset defaultSlippageBps` (restores 50).
- **`trade check` / MCP `trade_preview` liquidity threshold** is the resolved market-order bound for the venue (was a fixed 0.5%; equal under the shipped default).
- **Uniform not-supported errors** — `CAPABILITY_UNSUPPORTED` raised via `unsupported(venue, feature, reason, remediation)` now carries `details.{venue, feature, reason}`; messages read `<Venue> does not support <feature> — <reason>`.
- **API:** `ExchangeAdapter.marketOrder(symbol, side, size, opts: { reduceOnly; slippage })` and `SpotAdapter.spotMarketOrder(symbol, side, size, opts: { slippage })` take a required `ResolvedSlippage`; `OrderRequest.slippageBps` → `slippage: ResolvedSlippage | null`; `VenueDefinition.maxSlippageBps` added, `VenueSpotDefinition.perCallSlippage` removed.

### Venue-final IOC outcomes (design §13.10 #4 — ships with the tighter slippage bounds above)

#### BEHAVIOR CHANGES
- **A venue-reported final IOC / market fill is authoritative** for bot / arb / `trade multi` / plan perp legs (`placePerpVerified`) when the adapter implements `iocOutcomeOf(raw)` (new `IocOutcomeCapable`, `src/exchanges/ioc-outcome.ts`; adapter lanes add it for Hyperliquid / Lighter / Aster). The report is cross-checked against the measured position delta (tolerance one lot step):
  - final **0** filled and the position did not move → `ORDER_REJECTED` (definite; previously often `ORDER_PENDING`). A reduce-only order on a flat position carries `details.reduceOnlyFlat`. If the position did move, the measured delta is used and the discrepancy is logged to stderr.
  - final **partial** fill (any size) → accepted as `filledSize` (the 80% minimum no longer applies to venue-final outcomes); a delta that never agrees with the report → `ORDER_PENDING`.
  - Adapters without `iocOutcomeOf`, or a result it does not recognize → the existing measurement path (≥ 80% or `ORDER_PENDING`).
- **Accepted risk:** with 50 bps bounds a thin book can partially fill a close; `closePerpVerified` closes the residual once and reports what is still open (the caller quarantines).
- **Spot legs (`spotMarketFill`)** use `iocOutcomeOf` on spot results when available, in preference to the balance delta: final 0 + unchanged balance → `ORDER_REJECTED`; final > 0 must be backed by ≥ 80% of it in the fresh base-balance delta (else `ORDER_PENDING`).
- **Callers handle any partial fill:** spot-perp executor entry stops (manual / quarantine) when the perp short filled less than the spot held (previously reported success); `arb exec` spot-perp close flags a partial re-short / reduce as MANUAL (quarantine); `trade multi` reports a partially filled leg as `ORDER_PARTIAL` (with `--rollback` it stops and rolls the filled legs back); plan `close_position` closes the residual once (`closePerpVerified`) and fails with `ORDER_PARTIAL` when some is still open — its step result is now `{ symbol, side, size, closed }` instead of the raw venue response.
- **`getTakerFee` / `getMakerFee` no longer swallow settings errors** — a malformed `settings.json` now throws (`INVALID_PARAMS`) instead of silently using the built-in fees. The built-in per-venue taker fees remain the documented defaults when `settings.fees` has no entry.

- **Arcus spot** — refuses to sign an intent whose deadline is more than 5 minutes ahead, or whose EIP-712 types differ from the pinned Permit2 `PermitWitnessTransferFrom` / `TokenPermissions` / `TakerIntent` definitions; prints the USDG amount to spend (buy) / minimum to receive (sell) on stderr before signing and records it in `venueRaw` (`usdgSpend` / `usdgMinReceive`).
- **Arcus spot accepts `--no-agent`** with master credentials (spot swaps are master-signed); with neither an agent key nor a master key, adapter creation fails with `NO_SIGNER_AVAILABLE` (previously `AGENT_NOT_REGISTERED`).
- **Portfolio / landing page value Arcus (wallet) spot from held tokens only** (`getSpotPrices(tokens)`: one router `/price` per held token instead of the whole token universe) and bound each venue's spot valuation (adapter + balances + prices) by `SPOT_VALUATION_TIMEOUT_MS` (5 s) — a timeout is reported, not a $0 value.
- **Pacifica perp ignores spot orders** — `getOpenOrders()` excludes spot symbols (e.g. `SOL-USDC`) and `cancelAllOrders()` without a symbol cancels the perp orders one by one instead of `cancel_all` with `all_symbols: true` (which also cancelled spot orders).
- **Spot adapter cache** is keyed per perp adapter instance (its own network) + on-chain-approve option; read-only and signed perp adapters no longer evict each other's spot adapter, and a testnet perp adapter can no longer receive a spot adapter cached under the process network.
- **Quarantine for unknown / unhedged outcomes — global per symbol** (new `src/bot/quarantine.ts`, persisted in `~/.perp/bot-quarantine.json`). An `ORDER_PENDING` spot or perp leg, an unconfirmed perp leg, a failed or partial rollback, a dust-only entry fill, a rotation leg in an unknown state, repeated close failures, every spot-perp-executor `manual` outcome, a funding-arb-v2 position still open at stop, and a pending / MANUAL `arb exec spot:*` or `arb close` outcome quarantine the **symbol**: a `[QUARANTINE] CRITICAL` line with the remediation is logged, and **every** automated path — funding-arb, funding-arb-v2, spot-perp-arb, funding-auto, `arb exec` (perp-perp and `spot:*`, which fail with `RISK_VIOLATION`) and the `arb auto` daemon (entry and exit) — skips that symbol until a human clears it. Entries are stored per source (`<strategy|arb-exec|arb-close>:<SYMBOL>`) but checked by symbol. The file is re-read on every check, so **`perp strategy quarantine-clear <symbol> [--strategy <source>]`** takes effect in running bots on their next tick (no restart); only an entry whose persist failed lives in process memory. **`perp strategy quarantine`** lists. An unreadable quarantine file blocks (fail-closed), never "not quarantined".
- **Spot-perp executor `closePosition` returns `{ closed: false, manual: true, reason }`** for a pending spot sell, a failed post-sell verification, or a leg left unhedged (failed re-hedge); spot-perp-arb quarantines the position. The executor no longer opens a perp short when the spot sell fails on a retry where the perp was already gone (that would be a new naked position, not a rollback) — it quarantines instead. `openPosition` reports `manual: true` for a pending / unverified / dust spot buy or a failed entry rollback.
- **funding-arb spot-perp closes use the executor's close** (perp short first, reduce-only and verified; spot sold only after) instead of "sell spot → close perp → re-buy spot on failure". A perp already gone is detected by the reduce-only rejection before any spot is sold again; a plain failure cools down 5 min and **3 consecutive failed closes quarantine the symbol** (funding-arb and spot-perp-arb) — no sell→fail→rebuy / close→fail→re-hedge loop.
- **`arb auto` daemon manages perp-perp positions only** — persisted `spot-perp` positions (from `arb exec spot:*`) are skipped with a one-time warning (close them with `perp arb close <symbol>`) instead of being closed as perp-perp, and block a new perp-perp entry on the same symbol (state is keyed by symbol).
- **Lighter spot fills come from Lighter's own data** — `spotMarketOrder` reads the executed tx's `event_info` taker order (`is` / `rs`, validated against the sent base amount) and returns a `SpotOrderResult` (`filled` / `partial`, final). Only when the venue gives no fill report does `spotMarketFill()` fall back to the base-balance delta, now read **uncached**; a zero delta is `ORDER_PENDING`, and a failed read is never zero.
- **`SpotFreshBalancesCapable.getSpotBalancesFresh()`** (Lighter, Hyperliquid — adapters whose `getSpotBalances()` is served from the shared 15 s `acct:` cache) and `readSpotBalancesFresh()` in `spot-result.ts`; used for fill measurement, the spot-perp executor's pre/post-trade checks, and post-close quote sweeps.
- **Sweeps move only this trade's quote** — `sweepSpotQuoteToPerp(spot, min, { keep, max })` leaves the pre-trade spot quote untouched; `arb exec spot:*` sweeps back at most what it transferred in, `arb close` only the proceeds above the pre-close quote.

- **Order outcome classification (design §12.3).** New error code **`ORDER_REJECTED`** (not retryable): the order was definitely not placed (explicit venue rejection, or a failure before it was sent). `spotMarketFill()` rethrows a PerpError with a definite code (`isDefiniteOrderFailure`: validation, policy, signer, `ORDER_REJECTED`, …) and turns **anything else** thrown by the order call (non-PerpError, `EXCHANGE_UNREACHABLE`, `TIMEOUT`, `EXCHANGE_ERROR`, `RATE_LIMITED`, `UNKNOWN`) into `ORDER_PENDING`, so callers quarantine instead of retrying. The spot adapters type their own failures: everything before the request (market resolution, size / notional checks, reference price, nonce, signing, allowance) is `ORDER_REJECTED`; a transport error, timeout, HTTP 5xx or unreadable body after the request is `ORDER_PENDING` — Lighter / Lighter RH (`sendTx`; an explicit non-200 code and a failed tx status are `ORDER_REJECTED`), Hyperliquid (`{"status":"err"}` and a 0-fill IoC are `ORDER_REJECTED`; a missing per-order status or a resting IoC is `ORDER_PENDING`), Ondo (4xx venue envelope → `ORDER_REJECTED`, `RATE_LIMITED` kept), Aster (a network error after signing now returns a `pending` result; 4xx → `ORDER_REJECTED`), Arcus (a `/submit` body-read failure is `ORDER_PENDING`, router 4xx → `ORDER_REJECTED`).
- **Bot perp legs are verified, not assumed** — new `placePerpVerified()` (`src/bot/perp-order.ts`) measures every hedging perp leg as the position delta (uncached, polled): moved ≥ 80% of the size (or a reduce-only order flattened the position) = filled; no movement, an unreadable position, or a transport-type failure without movement = `ORDER_PENDING`. Used by the spot-perp executor (entry short, close, re-hedges, rotation), funding-arb (perp-perp legs, closes, rollbacks, spot-perp short) and funding-arb-v2. A Lighter market order that returned "assuming executed" without a fill is therefore quarantined, and an unknown perp outcome is never followed by a spot or long rollback (which could leave a naked short).
- **Lighter tx-event spot fills are cross-checked** — a fill parsed from `event_info` (`is` − `rs`) must be backed by a fresh base-balance delta of ≥ 80% inside `spotMarketFill()` (every caller), else `ORDER_PENDING`.
- **Spot-perp executor rotation returns `{ ok, manual, reason }`** — an unknown close / new-short outcome or a failed rollback re-open is `manual` (spot-perp-arb quarantines instead of a 10-minute cooldown); the new short is never followed by a re-open of the old one when its outcome is unknown (no double short).
- **Spot-perp executor close sweeps only this sale's proceeds** (quote delta since the pre-close read) back to perp, not the whole spot quote balance.
- **funding-arb perp-perp**: closes and the orphaned-short close are reduce-only (the orphan force-close was a plain order that could flip the position); a failed entry rollback (orphaned long), a failed close rollback (naked short) or a failed orphan close quarantines the symbol. The post-entry "phantom leg" rollback with swallowed errors is gone (legs are verified when placed).
- **funding-arb-v2 (the live strategy, `src/bot/strategies/funding-arb-v2.ts`)** — legs are placed one at a time and verified; a definite short failure rolls the long back reduce-only; closes are reduce-only with the size actually opened (previously re-derived from the current price, not reduce-only, and both legs in parallel — a one-leg failure left a naked leg); repeated close failures, unknown outcomes and failed rollbacks quarantine; **stopping the bot no longer drops tracked positions** (it closes them, and any it cannot close is quarantined with what is open); quarantined symbols are skipped.
- **Recovery never treats an unreadable venue as "no positions"** — funding-arb, spot-perp-arb and funding-auto log a failed position / spot-balance read, block entries on that venue, and (funding-arb, spot-perp-arb) retry the recovery every tick until it succeeds; funding-auto's stop reports venues it could not read.
- **Lighter / Lighter RH spot open orders** without a boolean `is_ask` throw `EXCHANGE_ERROR` instead of being reported as buys.
- **Untyped perp errors are never read as rejections** — `placePerpVerified()` rethrows only a typed definite failure (`isDefiniteOrderFailure`); any other error (including a plain `Error`) is measured as the position delta like a resolved order: moved ≥ 80% = filled, no movement = `ORDER_PENDING` (quarantine). Only a reduce-only order that failed with a plain venue message while the position was flat before and after is `ORDER_REJECTED` (venue message kept for `isPositionGone()`). Hyperliquid `HL exchange API error (5xx)` and Pacifica `POST … failed (5xx)` are classified as unknown outcome (`isUnknownOutcomeServerError()`).
- **`arb exec spot:*` and `arb close` (spot-perp) verify every perp order** with `placePerpVerified()` (entry short, entry reduce, buy-back, re-short, naked-short reduce). An unknown perp outcome quarantines the symbol and stops (`status: "perp_pending"`): no spot sell-back, no re-short, no state or transfer change. A position is persisted as hedged only with a verified perp fill, at the measured size; the old post-trade "filled_unverified" path is gone. A not-hedged entry reports what is actually left (spot held / perp short) instead of "Rolled back — no open exposure".
- **Quarantine matches the canonical symbol** — new `quarantineKey()` (uppercase, HIP-3 dex prefix and `-PERP` stripped, `DENOMINATION_ALIASES` applied: `KPEPE` ≡ `1000PEPE`, `xyz:TSLA` ≡ `TSLA`) is used for set, check and clear; existing file entries match by their computed key. Entries keep the symbol as reported for display.
- **funding-arb (perp-perp) and funding-arb-v2 size the short to the long's verified fill** (not the requested size). If the short fills less, the long is trimmed by exactly this trade's excess (reduce-only, verified, new `trimFirstLegToHedge()`); a failed or unknown trim quarantines. The tracked position size is the short's verified fill. funding-arb no longer calls `reconcileArbFills` (which acted on the venue's whole position) after entry.

- **Cross-venue matching rejects same-ticker / different-asset pairs** — funding comparison (`funding/rates.ts`) drops venues whose mark deviates more than `MAX_PRICE_DEVIATION_PCT` (5%) from the cross-venue median, and `arb scan` / `arb exec` / the `arb auto` daemon (`fetchFundingSpreads`) also require the chosen long/short pair to agree within 5%. Previously e.g. `PRL` (167% price gap) was offered as an arb. Excluded venues are reported once on stderr.

- **Aster in-process caches follow account invalidation** — Aster kept 5s in-memory snapshots of positions, balance and open orders that `invalidateCache("acct")` (used by every fill / residual verification) did not reach, so a post-order position read could return a pre-fill snapshot (false "pending" / quarantine). Snapshots now carry an account-cache epoch (`cache.ts accountCacheEpoch()`) and are dropped on every invalidation and every order write.

### Bot / arb order safety (`feat/venue-abstraction`, design §11 / §12.3)

Every remaining bot / arb order path now follows the §12.3 rules: fills are verified (`placePerpVerified` measures the position delta), closes / rollbacks / trims are reduce-only, an unknown outcome is never retried (the symbol is quarantined instead), legs are sequential (the second leg is sized to the first leg's verified fill, `trimFirstLegToHedge` removes any shortfall), and quarantine is checked before entry and exit.

#### BEHAVIOR CHANGES
- **`arb exec` (perp-perp) legs are sequential, not parallel** — long first, then the short sized to the long's VERIFIED fill. Each leg waits for position verification (up to ~6 s of polling), so an entry takes noticeably longer and the second leg fills at a later price than before. `--reconcile` is now always on (the long is trimmed reduce-only to the short's verified fill). JSON `status` is now `filled` / `not_filled` / `rolled_back` / `quarantined` (previously `filled_unverified`, `silent_reject`, `partial_fill`, `both_rejected`, `both_failed`); `openExposure` reports what may remain open.
- **A venue that accepts an order but whose position does not move is quarantined, not rolled back** (`arb exec`, `arb auto`, `arb dex-auto`, `funding-auto`) — the order may still execute. This also applies to `--smart` IOC legs that fill nothing. Clear with `perp strategy quarantine-clear <SYMBOL>` after checking the venues.
- **`arb exec` rejects venues without a trading role** (none currently registered) with `CAPABILITY_UNSUPPORTED`, for perp-perp legs and the perp leg of `spot:<venue>`.
- **`arb auto` daemon entries are sequential and verified** (same as `arb exec`); the persisted size is the verified hedged size. Entry sizes are floored (`toFixed(4)` rounding up is gone).
- **`arb auto` / `arb dex-auto` closes are sequential, reduce-only and verified, with no in-cycle retry.** A definite long-close failure (nothing changed) is retried next cycle and quarantines the pair after 3 consecutive failures; an unknown outcome, a partial close, or a short that fails after the long closed quarantines immediately and the position stays in state. `arb dex-auto` no longer drops a position from tracking when its close fails.
- **`arb close` (perp-perp) is reduce-only, verified, sequential, sized from the venue's own position size, and never retried** (previously 2 retries, non-reduce-only). An unknown outcome quarantines the symbol.
- **`arb close` refuses a quarantined symbol** (`RISK_VIOLATION`) for both the perp-perp and spot-perp paths unless `--force` is passed; `--force` prints a warning and does not clear the quarantine. `--dry-run` only warns.
- **`funding-auto` no longer has a spot-perp mode** — a non-zero `spotPerpRatio` fails at init with `CAPABILITY_UNSUPPORTED` (use `spot-perp-arb`); `spotPerpMinSpread` is removed and unmatched perp shorts are never adopted as "spot-perp". Its perp-perp entry is sequential and verified, its closes are reduce-only / verified / sized from the venue position, and it quarantines its own unknown or unhedged outcomes (and after 3 consecutive close failures).
- **`funding-auto` skips the exit decision for a pair when trade / funding history cannot be read** (logged) instead of treating fees and funding as 0.
- **`funding-arb` recovery rebuilds cross-venue spot-perp hedges** (spot on venue A, perp short on venue B) by canonical symbol; when the match is ambiguous (several venues hold the base, or the holding already backs another short) the symbol is quarantined instead of left untracked.
- **Bot `place_order` market actions pass `reduceOnly` to the adapter** (previously only limit orders did).
- **Lighter perp open orders / order history / trade history throw `EXCHANGE_ERROR` for a row without a boolean `is_ask`** instead of reporting it as a buy. `getOpenOrders` no longer hides that error as "no orders".
- **`trade close` / `close-all` / `flatten` / `reduce` send reduce-only market orders** on every venue (legacy adapters via `marketOrder(..., { reduceOnly: true })`; Ondo / Arcus via `placeOrder` with `reduceOnly: true`). `trade reduce` sizes from the position's own size string, floored to its decimals (100% = the exact position size), never larger than the position.
- **`funding-auto` perp-perp exit uses the SIGNED spread** for the held direction (short-venue hourly − long-venue hourly, each normalized by its funding basis, annualized) and closes when it is ≤ `perpPerpCloseSpread` (default now `0` in code too, matching the declared parameter default; previously the getter fell back to `5`, but the value was never used).
- **Ondo client requests time out** after `ONDO_REQUEST_TIMEOUT_MS` (15 s, fetch + body). A failed / timed-out GET is `TIMEOUT` / `EXCHANGE_UNREACHABLE`; a failed / timed-out POST (orders, stops, leverage, transfers, withdraw) is `ORDER_PENDING` (outcome unknown, do not resubmit). The Arcus REST client applies the same GET / POST classification to its existing 15 s timeout (POST failures were `EXCHANGE_UNREACHABLE`, i.e. retryable). The Arcus spot router already had a timeout and maps `/submit` failures to `ORDER_PENDING`.
- **`arb auto` basis-risk check reads each venue's own mark price** (data-driven column map); a venue without a mark-price column skips the check with an explicit warning.
- **HIP-3 position verification** (`signedPerpPosition`, used by `placePerpVerified` / `arb dex-auto`) matches the order symbol and the position coin through the HL adapter's dex resolution (`resolveSymbol` + dex prefix), so `TSLA` / `xyz:TSLA` / `XYZ:TSLA` name the same position.

#### Fixed

- **`funding-auto` perp-perp entry** sent both legs with `Promise.all` (one leg could fill alone, nothing rolled back); closes were not reduce-only and were sized with `toFixed` rounding that could exceed the position (`toFixed(0)` for sub-$1 assets).

#### Second pass — remaining order paths (2026-10-01)

New primitive `closePerpVerified()` (`src/bot/perp-order.ts`): a verified reduce-only close that, when the fill is short of the requested size (placePerpVerified accepts ≥ 80%), re-reads the position and sends ONE reduce-only market close of the measured residual; whatever is still open is returned as `residual` and the caller quarantines. Used by every close / rollback / trim below and by `closePerpPairVerified`, `openPerpPairVerified` (rollback) and `trimFirstLegToHedge` (a partial trim now throws `ORDER_PARTIAL` → quarantine).

##### BEHAVIOR CHANGES
- **`perp strategy funding-arb --auto-execute` is rebuilt on `openPerpPairVerified` / `closePerpPairVerified`** — legs are sequential and verified (long, then the short sized to the long's verified fill; a definite short failure rolls the long back reduce-only; an unknown outcome quarantines under source `funding-arb-cli`). Closes and the max-drawdown emergency close are reduce-only and sized from the venue position size string (capped at the tracked size); a leg already gone → the other leg is closed alone (reduce-only, verified). Quarantined symbols are never entered or closed. A lot-size rejection is never blindly resubmitted: a long DEFINITELY rejected for lot size (nothing placed) is re-sized once; a rejected short is placed once at the lot-floored verified long fill, and the long's excess is trimmed. The pair must also agree on mark price within `MAX_PRICE_DEVIATION_PCT`. Previously both legs went out with `Promise.all` (no reduce-only on close, a lot-size retry resent both legs, `reconcileArbFills` traded the venue's whole position non-reduce-only).
- **`trade multi` legs are placed one at a time and verified** (`placePerpVerified`; `--smart` sends each leg as an IOC limit verified the same way, no market fallback). With rollback on, the first definite failure stops further legs (`skipped`); filled legs are rolled back reduce-only, sized to the MEASURED fill, with one residual close. An unconfirmed leg is reported as `unknown`, its symbol is quarantined (source `trade-multi`) and NOTHING is rolled back; a rollback that fails / is unconfirmed / leaves a residual is `rollback_failed` and quarantined. Quarantined symbols are refused (`RISK_VIOLATION`). JSON legs carry `filledSize`; summary adds `unknown`, `skipped`, `rollbackFailed`, `quarantined`. **`--timeout` was removed** (passing it is `INVALID_PARAMS`): the old `Promise.race` "Leg timeout" reported a possibly-filled leg as failed.
- **Closes / rollbacks no longer accept an 80–99% fill silently** — funding-arb (bot) entry rollback and perp-perp close (both legs, orphaned short), funding-arb-v2 rollback / close, funding-auto rollback / close, spot-perp close and rotation, arb pair closes: one reduce-only residual close, then quarantine if anything remains. A re-opened leg (hedge restore) that fills less than requested quarantines. funding-arb spot-perp entry quarantines when the perp short fills less than the spot bought (tracked size = verified short).
- **spot-perp close sells only the verified perp close** when a perp residual remains (the unsold spot still hedges it; the symbol is quarantined); the hedge restored after a failed spot sell is the measured close, not the requested size. Rotation opens the new short at the verified close of the old one.
- **`arb exec spot:<venue>` never reports `filled` with unbalanced legs** — the excess-short reduce is one verified reduce-only close (no second attempt); if it fails or the verified short is below the spot held, the symbol is quarantined and the result is `status: "quarantined"` with `exposure: { spotHeld, perpShort }`.
- **`smartOrder` failures that place nothing are typed `ORDER_REJECTED`** (orderbook read failure, empty book side, unusable limit price, an exchange rejection embedded in the response, an explicit IOC no-match status with `executedQty` 0), so `placePerpVerified` no longer quarantines a `--smart` leg that never traded. A zero-fill IOC the venue does not report explicitly (e.g. Lighter) is still measured and may quarantine.
- **`placePerpVerified` reads a plain "not a multiple of lot size N" rejection with the position measured unchanged as `ORDER_REJECTED`** (`details.lotSize`, `rejectedLotSize()`); the reduce-only "no position" rejection carries `details.reduceOnlyFlat`.
- **`isPositionGone()` takes the error** and checks the typed flag first (`ORDER_REJECTED` + `reduceOnlyFlat`; never for `ORDER_PENDING`), then venue texts incl. `(no X position to reduce)` and HL `Reduce only order would increase position`.
- **`perp strategy trailing-stop` re-reads the position at trigger time** and closes the live size reduce-only and verified (residual → `ORDER_PARTIAL` error, unknown → `ORDER_PENDING`); a position already gone ends with `reason: "position_gone"` (nothing sent). Previously it sent a plain market order with the size seen at start (could flip a position).
- **Plan `close_position` is reduce-only**, sized from the live position.
- **MCP tools return the structured error** (`code`, `retryable`, `remediation`, `details` next to `error`) instead of the message only. `trade_execute` / `trade_close` map any non-definite order failure to `ORDER_PENDING` with a "do NOT resubmit — check positions first" remediation (previously a transport error surfaced as retryable `EXCHANGE_UNREACHABLE`).
- **Funding comparison (`funding/rates.ts`) also checks the chosen long/short pair** for a mark gap > `MAX_PRICE_DEVIATION_PCT` (the median filter let a 2-venue group through at up to 2× the limit).

#### Third pass — mainnet blockers (2026-10-01)

##### BEHAVIOR CHANGES
- **MCP `trade_execute` never turns a placed order into an error** — the post-order position read is uncached and wrapped; if it fails the result is still `ok: true` with `currentPosition: null` and a `warning` ("do NOT resubmit"). Previously a read failure after a successful order returned a retryable error and an agent could place the order twice. `trade_close` (the only other MCP order tool) has no post-order read; its pre-close position read is now uncached.
- **Adapter pre-send failures are typed, so they are no longer reported as `ORDER_PENDING`** (messages unchanged, a code added):
  - Lighter: unknown market → `SYMBOL_NOT_FOUND`; no mark price → `PRICE_STALE`; market decimals not loaded → `ORDER_REJECTED`; size below the market precision → `SIZE_TOO_SMALL`; price below the precision → `INVALID_PARAMS`; signer missing (`ensureSigner`) → `NO_SIGNER_AVAILABLE`; signer error / empty txInfo / no txType → `SIGNATURE_FAILED`. Every other failure before `sendTx` in `marketOrder` / `limitOrder` / `stopOrder` (nonce read, market map, signing) → `ORDER_REJECTED` (`orderNotSent`).
  - Hyperliquid: unknown asset → `SYMBOL_NOT_FOUND`; a per-order venue error status and an IOC zero fill (`order not filled (0 of N)`) → `ORDER_REJECTED` (an IOC reported *resting* stays untyped = unknown); HIP-3 dex market order with no mark price → `PRICE_STALE`; L1 action signing failure → `SIGNATURE_FAILED`.
  - Aster: a market order whose poll shows `CANCELED` / `EXPIRED` / `REJECTED`, an immediate 0-fill with such a terminal status, and the "not filled after 3s, cancelled" case when the cancel was confirmed with 0 executed → `ORDER_REJECTED` (a failed cancel stays untyped = unknown); request signing failure → `ORDER_REJECTED`.
  - Pacifica: `success: false` / `error` in the order response and a poll status `cancelled` / `rejected` with 0 filled → `ORDER_REJECTED`; request signing failure → `ORDER_REJECTED`.
  - Arcus: the (unreachable) missing client id guard → `INVALID_PARAMS`.
- **`PRICE_STALE` counts as a definite order failure** (`DEFINITE_ORDER_FAILURE_CODES`): it is only raised before an order is built / sent.
- **`perp plan execute`**: `market_order` and `close_position` steps are verified by the position delta (`placePerpVerified`); a limit / stop step that throws anything but a definite rejection is `ORDER_PENDING`. An order step with an unknown outcome is `status: "pending"` — the plan stops, the symbol is quarantined (source `plan-execute`) and that step is never rolled back. `onFailure: "rollback"` now actually reverses filled market-order steps (reduce-only `closePerpVerified` for the MEASURED fill) and cancels resting orders only on the plan step's symbol (previously `cancelAllOrders()` on every symbol, errors swallowed, fills left open); a reversal that fails is `rollback_failed` and quarantined, reversed steps become `rolled_back`. `dependsOn` now blocks unless the dependency succeeded (a skipped / pending / rolled-back dependency used to let the step run). `PlanResult.status` adds `pending` / `quarantined`; `PlanResult.quarantined` lists the symbols.
- **funding-arb (bot) perp-perp close**: the long is never re-opened when the short close fails (a non-reduce-only order that could loop close → fail → re-open every tick) — a short close that definitely failed after the long closed quarantines immediately (as `closePerpPairVerified`); 3 consecutive definite long-close failures quarantine (same `MAX_CLOSE_FAILURES` as funding-arb-v2 / funding-auto).
- **funding-arb-v2 close**: long closed + short close definitely failed → quarantined immediately (previously the naked short was carried across up to 3 ticks).
- **Reduce-only closes are sized from an uncached position read**: `perp strategy funding-arb` close, trailing-stop trigger, MCP `trade_close`, `arb close` spot-perp, plan `close_position`.
- **`trade multi` and `arb exec` exit with code 1 and, in JSON mode, an `ok: false` envelope** when the outcome is not a success, with the full structured result in `error.details`: `ORDER_PENDING` (unknown leg / perp or spot pending), `ORDER_PARTIAL` (quarantined / rollback failed / legs left filled next to a failed one), `ORDER_REJECTED` (failed, nothing left open). `arb exec` pre-trade aborts (same venue, leverage failure, insufficient depth, below minimum) are `INVALID_PARAMS` / `EXCHANGE_ERROR` / `SIZE_TOO_LARGE` / `SIZE_TOO_SMALL` instead of `ok: true` with an `error` field.

## [0.12.0] — 2026-05-01

### Added
- **SSOT Rule #3** (Single Secret Source per Key) — see `docs/SSOT_RULES.md`.
- Lighter L2 keystore at `~/.perp/lighter-agents/<account>-<slot>.json` (AES-256-GCM, mode 0600). Replaces plaintext env storage.
- One-time auto-migration of legacy `LIGHTER_API_KEY` env to encrypted keystore.
- `wallet show --json` now exposes `owsActive: { name, evmAddress, solanaAddress }` so agents can discover the master EVM/Solana address without env-derived fallbacks.
- Lighter referral apply is now L2-signed (works via agent path; previously gated by master `pk`).

### Changed
- Referral codes are now mandatory — `settings.referrals` field and `settings referrals on/off` command removed. Pacifica's builder code was already always-on; HL/LT aligned.
- `~/.perp/.env` is the only auto-loaded env file. CWD `.env` auto-load removed (was a Rule #3 violation surface).

### Fixed
- Referral apply `.catch` no longer marks `applied=true` on failure (SSOT Rule #2). Failures propagate to stderr; `referralApplied` stays false until next try.

### Security
- Lighter L2 slot key is no longer stored in `.env` plaintext. Aligned with Aster/HL/PAC agents which were already in OWS vault.
